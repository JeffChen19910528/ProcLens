# ProcLens 安全決策

[English](../SECURITY.md) | **繁體中文**

對這些決策的審查，以及審查所發現並修正的缺陷，記錄於 `SECURITY_REVIEW.md`。

本文記錄出於安全理由而存在的決策，以免日後被「簡化」掉。它描述的是目前已實作的內容；第 8 節列出**尚未完成**的項目，第 9 節列出已知限制。

## 1. 處理程序傾印（僅限 Windows）

傾印是處理程序記憶體的副本。它可能包含密碼、權杖、工作階段資料、加密金鑰與個人資訊。以下所有內容都源於此。

### 誰可以被傾印
- 操作者**擁有**的處理程序可以被傾印。屬於他人的處理程序會被拒絕，除非第 4 節的系統管理員授權成功。若無法判斷擁有者，要求會被**拒絕**
  （失敗即封閉）；例如 `audiodg` 對未提升權限的使用者會公開啟動時間，卻不公開擁有者。
- 這項檢查在以記憶體讀取權限開啟目標之前執行。
- ProcLens 絕不提升權限、絕不啟用 `SeDebugPrivilege`、絕不繞過 Protected Process Light、絕不注入程式碼。若 Windows 拒絕存取，結果是 `AccessDenied`，並附上說明訊息。
- ProcLens 拒絕傾印**它自己**（從目標內部呼叫 `MiniDumpWriteDump` 並不可靠）。

### 要求的權限
- 每種傾印類型都剛好是 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`（`WindowsProcessDumpProvider.RequiredAccess`）。絕不使用 `PROCESS_ALL_ACCESS`。
- 刻意不使用 `MiniDumpWithHandleData`。它需要更多權限，並會記錄目標所開啟核心物件的名稱。

### 處理程序身分
- 呼叫端提供它所觀察到的啟動時間。提供者**先**開啟處理程序（持有的控制代碼會鎖定處理程序物件，因此 PID 不可能在底下被回收），
  接著將該控制代碼的 `GetProcessTimes` 與預期值比較。等待 DbgHelp 閘門之後會再檢查一次，因為等待可能很久。

### 輸出位置與檔案
- 檔案以 `FileMode.CreateNew`（絕不覆寫）、`FileShare.None`，以及只有**一筆**目前使用者項目且移除繼承的 ACL 建立（Unix 上為模式 0600）。
  系統管理員與 SYSTEM 刻意不列入；系統管理員仍可取得所有權，而這是 Windows 會稽核的。
- ProcLens **建立**的目錄僅限目前使用者存取。對既有目錄，ProcLens 不會變更其權限；若 Everyone、Users 或 Authenticated Users
  可列出其內容，則會發出警告（檔案本身仍是私有的，但檔名會洩漏處理程序名稱與識別碼）。
- 檔名是自動產生的；呼叫端只提供目錄，因此名稱無法逃出該目錄。若目錄是檔案、裝置路徑（`\\.\`）或符號連結／連接點，則會被拒絕。
- 任何失敗或取消都會移除不完整的傾印、暫存的明文與中繼資料。

### 原生程式碼
- DbgHelp 以 `DllImportSearchPath.System32` 匯入，因此被植入的 `dbghelp.dll` 永遠不會被載入。
- 所有 DbgHelp 呼叫都經過同一個靜態 `SemaphoreSlim`（DbgHelp 不是執行緒安全的），跨提供者執行個體皆然。
- 處理程序、權杖與快照的控制代碼都是 `SafeHandle`。

## 2. 靜態加密

傾印**預設加密**（`--no-encrypt` 可選擇不加密，並會被回報為「NOT protected」）。

- **加密器：** 分塊 AES-256-GCM（`PLENC001`），因為傾印檔可能有數 GB，而一次性的 AES-GCM API 無法串流。每個 1 MiB 區塊都以
  固定標頭 + 區塊索引 + 「最後一塊」旗標作為附加驗證資料來驗證，nonce 則由檔案的隨機前綴與索引組成。重新排序、遺漏、重複、截斷
  （即使在區塊邊界）、延長，或將區塊搬到另一個檔案，都會導致驗證失敗。
- **金鑰：** 每個檔案都有隨機的 256 位元資料金鑰。它被包裝在一個或多個**金鑰槽**中；資料金鑰絕不以未包裝的形式儲存。
  - *電腦／使用者槽：* 由以 **DPAPI（CurrentUser）** 保護的每使用者主金鑰包裝。只有同一台機器上的同一個 Windows 使用者能還原它。
    主金鑰絕不直接加密傾印內容。
  - *密碼槽：* PBKDF2-HMAC-SHA256（600,000 次迭代、隨機 salt）。最少 12 個字元。要求少於 10,000 或多於 3,000,000 次迭代的檔案會被拒絕
    （過於薄弱／CPU 阻斷服務）。
- **密碼絕不從命令列引數取得**（它們會出現在處理程序清單與殼層歷史中）：請使用 `--password-env <變數>` 或隱藏輸入的 `--password-prompt`。
  內部以 `SecretText` 保存，它沒有任何會經由 `ToString`、記錄或 JSON 洩漏的存取子，並在釋放時抹除。
- **暫存明文：** MiniDumpWriteDump 需要真正的檔案，因此原始傾印會短暫地以 `*.dmp.plain.tmp` 存在。它以私有方式建立、驗證、加密，
  加密後的副本會被**再次解密並比對雜湊**，之後明文才會以零覆寫並刪除。若無法移除，該操作即失敗。當機時可能殘留這個暫存檔（僅您可存取）；請刪除它。
- **匯出：** `dump export` 將資料金鑰重新包裝成僅密碼。資料不會重新加密，原檔不受影響，且刻意不帶入電腦金鑰，使副本可以離開這台機器。
- **解密：** `dump decrypt` 會寫入新的明文檔（絕不覆寫）並明確告知。輸出僅在每個區塊驗證通過後逐塊產生，任何失敗都會將其刪除。
- 遺失 DPAPI 主金鑰（新的使用者設定檔、重新安裝 Windows）會使僅受其保護的傾印無法讀取。請以密碼匯出重要的傾印，或在建立時加上 `--password-env`。

## 3. 稽核記錄

- JSON Lines、僅附加，預設位於 `%LOCALAPPDATA%\ProcLens\audit\audit.jsonl`（可用 `PROCLENS_AUDIT_LOG` 覆寫），建立時僅限目前使用者存取。
- 每次 `dump create`、`dump decrypt`、`dump export` 與 `dump verify` 都會被記錄，包括拒絕與失敗：操作者、是否提升權限、機器、操作、
  目標 pid／名稱／啟動時間／擁有者、傾印類型、位置、授權（是否允許、依據哪項原則、原因）、結果、錯誤、所儲存檔案的 SHA256、是否加密，
  以及系統管理員的理由。
- **絕不記錄：** 密碼、金鑰內容、記憶體內容。沒有欄位可存放它們；自由文字有長度限制並移除控制字元，因此一個值無法開啟第二筆記錄。
- **竄改證據（及其限制）：** 每筆記錄儲存前一筆的雜湊與自己的雜湊。`proclens audit verify` 可偵測單一筆被編輯、插入、刪除或重新排序的記錄，
  並回報第一個損壞的行。**雜湊沒有使用金鑰**，因此能寫入該檔案的人可以一致地重建整條鏈，而從結尾截掉記錄是看不出來的。對策是**錨點**：
  `audit verify` 會印出檔頭雜湊；請把它存放在記錄寫入者無法更改之處（工單、另一台主機），之後執行 `audit verify --anchor <hash>`，
  若該記錄已消失或它之前的任何內容被改寫，驗證就會失敗。
- **失敗即封閉：** 若稽核記錄無法寫入，特權操作會在開始前被**拒絕**。若事後無法寫入記錄，結果會帶有明顯的警告。
- 附加時會取得獨占鎖並以帶抖動的重試進行，因此多個 ProcLens 處理程序不會讓雜湊鏈分岔。

## 4. 系統管理員授權

傾印屬於其他使用者的處理程序，需要**全部**符合：
1. 該指令帶有 `--authorize-admin` 與 `--reason "<理由>"`（理由會被稽核）；
2. ProcLens 已經以**提升權限**執行：它絕不自行提升；
3. 有啟用此功能的本機原則：`%ProgramData%\ProcLens\policy.json`（可用 `PROCLENS_POLICY` 覆寫），
   `{ "AdminDumpsEnabled": true, "AllowedOperators": ["DOMAIN\\user"], "RequireReason": true, "MinReasonLength": 10 }`；
4. 若存在 `AllowedOperators` 清單，操作者必須在其中。

原則缺失、無法讀取或無效，都表示**停用**。作業系統仍決定提升後的權杖能開啟什麼，且 Protected Process Light 不會被繞過。
此原則是課責控制，而不是對系統管理員的邊界，因為系統管理員可以編輯它。

### 保護原則檔

在預設的 Windows 安裝上，**任何一般使用者都能在 `C:\ProgramData` 底下建立檔案**，因此預設位置的原則檔可能被他人植入
（安全審查已實證這點；見 `SECURITY_REVIEW.md`，F1）。因此 ProcLens 只有在一般使用者不可能寫入該檔案時，才會採信預設位置的檔案：

- **Windows：** 檔案*及*其資料夾的擁有者是 Administrators、SYSTEM 或 TrustedInstaller，且沒有其他帳戶對兩者擁有修改、取代、刪除或接管的權限
  （建立子資料夾沒問題）。
- **Unix：** 檔案及其資料夾都不可被群組或其他人寫入（預設位置在 `/etc` 底下）。

否則該檔案會被**忽略**（系統管理員傾印維持停用，保留使用預設值），並由 `proclens policy show` 說明原因。以 `PROCLENS_POLICY` 指定的路徑則被信任：
那是操作者自己的決定。

要在 Windows 上建立受保護的原則，請在**提升權限**的 PowerShell 中執行（這些指令實現了上述規則，但作者無法在提升權限下執行過；
請用 `proclens policy show` 檢查結果，如有不符請回報）：

```powershell
$dir = Join-Path $env:ProgramData 'ProcLens'
New-Item -ItemType Directory -Force $dir | Out-Null
icacls $dir /setowner "Administrators" | Out-Null
icacls $dir /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "Administrators:(OI)(CI)F" "Users:(OI)(CI)RX" | Out-Null
Set-Content -Path (Join-Path $dir 'policy.json') -Value '{ "AdminDumpsEnabled": true }'
icacls (Join-Path $dir 'policy.json') /setowner "Administrators" | Out-Null
proclens policy show
```

## 5. 保留與刪除

絕不會自動或在背景刪除任何東西。`proclens dump prune --directory <目錄>` 會套用保留原則，除非指定 `--delete`，否則只是**試執行**。

- **原則：** 本機原則檔（與第 4 節同一個檔案）中的 `{ "Retention": { "MaxAgeDays": 30, "MaxCount": 10, "MaxTotalMegabytes": 2048 } }`。
  規則會合併：只要任一規則選中，傾印就會被選取。預設為 30 天且無其他限制；區段缺失、無法讀取或無效時使用預設值，絕不會是「全部保留」或「全部刪除」。
  `--older-than-days`、`--keep` 與 `--max-size-mb` 可針對單次執行覆寫。
- **只處理 ProcLens 自己的傾印：** 只有當中繼資料檔可解析且指向同一個檔案時，傾印才受管理。不相關的檔案、單獨的 `.dmp` 檔、
  不符或損毀的中繼資料、子目錄與符號連結，絕不會被移除（它們會列為已略過）。本身是符號連結的目錄會被拒絕。
- **時間** 取自記錄的建立時間。日期在未來的傾印（時鐘偏差）不會因時間而被移除。
- **被中斷的傾印：** 殘留且超過一小時的 `*.dmp.plain.tmp` 檔案（當機遺留的原始記憶體）會被移除；較新的可能屬於進行中的傾印，會保留。
  只有 ProcLens 產生的名稱會符合。
- **檔案如何移除：** 未加密的傾印會先以零覆寫再刪除；加密的傾印直接刪除即可，因為其內容受金鑰保護。若檔案無法移除（例如正在使用中），
  會回報為失敗並保留其中繼資料，使其仍受管理。
- **課責：** 每次移除都會寫入 `dump.delete` 稽核記錄（原因、目標、雜湊、結果）。若稽核記錄無法寫入，`--delete` 會拒絕執行。
- **刪除的限制：** 覆寫並不保證在 SSD、寫入時複製或日誌式檔案系統、快照或備份上完全抹除。對加密的傾印，實際的保證是銷毀金鑰：
  別處的副本對任何持有金鑰或密碼的人仍然可讀。若想定期執行，請從作業系統的工作排程器執行 `dump prune`。

## 6. 診斷報告

`proclens report generate`（JSON、HTML 或 TXT）只收集處理程序中繼資料：身分、擁有者、路徑、CPU 與記憶體數字、執行緒與模組清單、功能，
以及在 Windows 上此處理程序傾印的中繼資料。

- **絕不包含記憶體內容與命令列**；報告模型沒有欄位可存放它們。
- **惡意的處理程序資料無法攻擊讀者。** 名稱、路徑、擁有者與執行緒名稱來自被檢視的處理程序，可能被精心構造。每個這類字串都會移除控制字元、
  換行與 Unicode 方向覆寫字元，因此 TXT 報告不可能被構造出偽造的行或章節。HTML 還會對每個值做 HTML 編碼，不含腳本、事件處理常式或外部資源，
  並宣告 `Content-Security-Policy: default-src 'none'`。
- **`--output` 會寫入僅限目前使用者可讀的新檔案**（0600／單一 ACE 的 ACL），且絕不覆寫。
- 報告揭露的是作業系統讓您檢視的內容（處理程序名稱、路徑、擁有者）。請將它們視為內部文件。
- 報告會列出磁碟上的傾印，並在此處理程序有未加密的傾印時發出警告（`UNENCRYPTED_DUMP`）。
- 產生報告屬於檢視，不是特權動作，因此不會寫入稽核記錄。

## 7. 處理程序檢視
- 沒有隱匿式檢視，也不變更權限。無法讀取的資訊會以原因回報為無法取得，絕不當成零；各處理程序的檢視會回傳明確的狀態
  （找不到／不支援／存取被拒／架構不相符）。
- 檢視（而非傾印）其他使用者的處理程序，僅受限於作業系統允許一般使用者讀取的範圍。

## 8. 尚未完成
- 沒有排程器：保留只有在呼叫 `dump prune --delete` 時才執行。
- 稽核記錄的**結尾截斷**與整個刪除，單憑檔案本身無法偵測；請使用外部錨點（`audit verify --anchor`），或將記錄送到另一個系統。
- **原始傾印在加密之前會接觸磁碟**（短暫、私有、抹除）。若能經由 DbgHelp 的 I/O 回呼直接串流到加密器，就能完全避免，但尚未嘗試。
- 主金鑰沒有輪替或備份工具。
- 沒有程式碼簽章、沒有套件鎖定檔；已接受與未解決風險的完整清單見 `SECURITY_REVIEW.md` 第 5 節。
- Linux／macOS 依設計沒有傾印功能；它們的檔案權限處理（0600）只在 Linux 上有測試涵蓋，而且**這裡的任何內容都未在 macOS 上執行過**。

## 9. 已知限制
- 以相同使用者身分執行的程式碼，可以讀取相同的處理程序與相同的金鑰；擁有者規則與 DPAPI 能限制意外與其他使用者，
  但它們不是針對您工作階段中惡意程式的沙箱。
- 單純覆寫無法在 SSD、日誌式／寫入時複製的檔案系統，或有快照的磁碟區上安全地抹除資料。請將刪除視為盡力而為。
- SHA256 值用來偵測損毀與竄改；它們不是存取控制。AES-GCM 驗證保護加密的傾印；未加密的傾印（`--no-encrypt`）僅仰賴檔案權限。
