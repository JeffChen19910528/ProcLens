# 平台支援

[English](../PLATFORM_SUPPORT.md) | **繁體中文**

ProcLens 在啟動時偵測作業系統，並且只提供該平台真正實作的功能。不支援的功能絕不會被列為可用；
`proclens system capabilities` 永遠如實告知目前這台機器的狀況。平台無法提供某個值時，ProcLens 會顯示「不支援」或
「n/a（原因）」，絕不把它當成零。

## 1. 功能矩陣

| 功能 | Windows | Linux | macOS |
|---|---|---|---|
| 處理程序列舉、身分、執行檔路徑、啟動時間 | 是 | 是 | 是 |
| 父處理程序識別碼 | 是 | 是 | **n/a**（受控 API 未公開） |
| 擁有者 | 是（在可開啟權杖時） | 是（使用者名稱，或數字 uid） | **n/a** |
| CPU 時間與 CPU %（取樣） | 是 | 是 | 是 |
| 工作集／虛擬／尖峰工作集 | 是 | 是（`VmRSS` / `VmSize` / `VmHWM`） | 是（在作業系統有回報時） |
| 私有記憶體 | 是 | **n/a**（`/proc` 沒有對應項目） | 有回報時才有 |
| 執行緒清單 | 是（含等待原因） | 是（含名稱與狀態） | 是，但**狀態永遠是 `Unknown`** |
| 模組清單 | 是 | 是（來自 `/proc/<pid>/maps`） | **不支援** |
| 處理程序生命週期監視 | 是 | 是 | 是 |
| 診斷報告（txt / html / json） | 是 | 是 | 是 |
| 稽核記錄檢視與驗證 | 是 | 是 | 是 |
| **處理程序傾印**（`dump create`） | **是** | **否，刻意如此** | **否，刻意如此** |
| 傾印加密、解密、匯出、驗證、資訊、清理 | 是 | 否 | 否 |

處理程序傾印刻意只支援 Windows。在 Linux 與 macOS 上，ProcLens 不會執行 `gcore`、不使用 `ptrace`，也不使用任何其他原生機制：
指令會印出

```
Process dump is not supported on this operating system.
Supported platform: Windows.
```

並以結束代碼 2 結束，不會建立任何東西。因此 `dump` 系列指令只限 Windows，包括只讀取檔案的那些指令，因為其他平台根本不會產生這些檔案。

## 2. 實際驗證過的範圍

這張表談的是證據，而不是意圖。

| | Windows | Linux | macOS |
|---|---|---|---|
| 建置 | 是，Windows 11（組建 26300）、.NET 10 SDK | 是，WSL2 下的 Ubuntu 24.04（核心 6.6） | 作為方案的一部分可編譯；**從未執行** |
| 自動化測試 | 通過，包括針對真實處理程序的即時測試 | 通過，包括即時 `/proc` 測試 | **即時測試存在但從未執行** |
| 與原生工具比對 | CPU 對照效能計數器；記憶體對照 `Get-Process` | CPU、記憶體、識別碼、執行緒與模組對照 `ps`、`ps -T` 與 `/proc` | 否 |
| 傾印 | 已建立、解密，並由獨立解析器（ClrMD）與 DbgHelp 開啟 | 不適用 | 不適用 |
| 在實體 Windows ARM64、Linux ARM64 或 Intel Mac 上執行 | 否 | 否 | 否 |

`.github/workflows/ci.yml` 會在 `windows-latest`、`ubuntu-latest` 與 `macos-latest` 上建置並測試。它尚未執行過；在執行之前，
所有關於 macOS（與 ARM）的部分都未經確認。在 `MacOSLiveTests` 於真實機器上通過之前，**請將 macOS 支援視為未經測試**。

## 3. Windows

- **版本：** .NET 10 所支援的 Windows 版本（見 Microsoft 的支援矩陣）。已在 Windows 11 x64 上測試；ARM64 封裝已建置但未測試。
- **檢視** 使用 toolhelp 快照以及處理程序、執行緒與模組 API。擁有者來自處理程序權杖；受保護的處理程序與其他使用者的處理程序，
  通常會把擁有者顯示為 `n/a`。
- **64 位元的 ProcLens 可以讀取 32 位元處理程序**（其 32 位元與 WOW64 模組都會出現）。32 位元的 ProcLens 無法讀取 64 位元處理程序的模組，
  並會回報*架構不相符*（結束代碼 4），而不是「存取被拒」。
- **傾印** 需要 DbgHelp（一律位於 System32）與用於電腦金鑰的 DPAPI。傾印檔以只有這台機器上您的 Windows 帳戶才能還原的金鑰加密；
  `dump export` 會產生一份可搬移、以密碼保護的副本。
- **受保護的處理程序**（Protected Process Light、`System` 處理程序、防惡意程式服務）無法以一般帳戶傾印，或讀取其模組。
  ProcLens 不會嘗試繞過，而是回報存取被拒。
- **系統管理員傾印** 其他使用者的處理程序，需要提升權限的殼層與啟用此功能的本機原則；見 `CLI_USAGE.md`。

## 4. Linux

- **版本：** .NET 10 在 glibc 上支援的發行版（已建置 x64 與 ARM64 封裝；只有 Ubuntu 24.04 上的 x64 實際執行過）。
  以 musl 為基礎的發行版（Alpine）沒有提供封裝；請以 `-r linux-musl-x64` 從原始碼建置。
- **檢視** 讀取 `/proc`。一般規則適用：`hidepid` 或您的帳戶所隱藏的內容，ProcLens 看不到。
- **CPU 時間** 假設 `USER_HZ` = 100 來把時脈週期換算成秒，這對所有主流核心組建都成立（以 `getconf CLK_TCK` 確認過）；
  啟動時間的換算在測試中會與執行階段交叉比對。
- **模組** 來自 `/proc/<pid>/maps`：每個具有可執行區段、以檔案為基礎的對應，以最低位址作為基底、涵蓋範圍作為大小。
  讀取其他使用者的 `maps` 需要 ptrace 讀取權限，因此一般使用者對這些會得到*存取被拒*。僅是記憶體對應的資料檔不會列出。
- **執行緒** 來自 `/proc/<pid>/task`；狀態字母會被對應（`R` 執行中、`S`/`I` 睡眠、`D` 等待、`T`/`t` 已停止、`Z`/`X` 已終止）。
- **私有記憶體** 無法取得：`/proc` 沒有對應 Windows「私有位元組」的項目，而 ProcLens 不會以別的量來替代。

## 5. macOS

- **版本：** .NET 10 所支援的 macOS 版本（見 Microsoft 的支援矩陣），Apple 晶片或 Intel 皆可。兩種封裝都已建置；**皆未執行過**。
- 檢視使用受控的 `System.Diagnostics.Process` API。
- **無法取得：** 父處理程序識別碼、擁有者、已載入的模組（尚未實作原生 dyld 列舉），以及執行緒狀態。這些會顯示為
  `n/a`／*不支援*／`Unknown`，並不算收集錯誤。
- 其他使用者與系統保護的處理程序，預期會對一般帳戶拒絕部分查詢；ProcLens 會將其回報為無法存取，但這點在 Mac 上並未實際觀察過。
- 封裝沒有程式碼簽章或公證，因此 Gatekeeper 會在第一次執行時阻擋；見 `TROUBLESHOOTING.md`。

## 6. 跨平台一致地解讀數字

- **CPU %** 一律以兩種方式顯示：佔**整機**的百分比（除以邏輯處理器數）與佔**單一核心**的百分比（可超過 100）。兩者都需要兩筆樣本；
  單一讀數不會產生使用率。
- **記憶體** 保留四種獨立的量（工作集、私有、虛擬、尖峰工作集），絕不合併。它們的含義在不同作業系統上略有差異
  （Linux 是常駐集，Windows 是工作集）；報告會指出哪些是 `n/a`。
- **時間** 除非欄位另有說明，否則一律以 UTC 儲存與顯示。
- **報告** 在每個平台上的結構、章節順序與狀態詞彙都相同，且一律使用 LF 換行。

## 7. 新增或變更平台功能

只有在平台的提供者宣告（`IPlatformProcessProvider.GetCapabilities`）時，功能才存在。指令層會詢問功能登錄表，因此宣告支援一個尚未實作的東西
就是錯誤，測試也會斷言所宣告的集合。見 `ARCHITECTURE.md` 的「擴充 ProcLens」一節。
